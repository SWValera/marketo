## Подтверждённая причина отказа двух обычных фото

В vinext 0.0.50 multipart POST ошибочно проходит через обработку Server Actions
до вызова upload API. Там действует лимит **1 МиБ**, независимо от собственных
ограничений фото. На точной опубликованной сборке два файла по 600 КиБ дают
413 `Payload Too Large`; два по 128 КиБ доходят до проверки авторизации (401).
Форма представляла любой 413 как «Общий размер фотографий слишком большой».

`build/multipart-route-guard.ts` исправляет только маршрут загрузки фото
объявления, который имеет собственные CSRF, auth, owner и bounded-body проверки.
Лимит Server Actions не увеличен; другие API и формы не изменены. Vite применяет
адаптер воспроизводимо, а изменение ожидаемого кода зависимости блокирует сборку.
`node_modules` и готовый `dist` вручную не исправлялись.

Один и тот же `tests/photo-worker.test.mjs`: прежний опубликованный артефакт
проваливает утверждение `413 !== 401`; исправленный проходит. Также проверены
403 для чужого origin и сохранение 413 для большой обычной формы страницы.
Использован настоящий локальный workerd и неизменённый скомпилированный Worker.
Тестовый gateway полностью читает входящий запрос до передачи через service
binding: это обход дефекта локального HTTP-транспорта, воспроизведённого на Windows,
который теряет chunked-ответ при раннем отказе большой непрочитанной загрузки.
Gateway существует **только в тесте**, не в приложении или конфигурации выпуска.

## Что изменено по уточнению пользователя

- Максимум **7**, включая существующие фото. Источник значения общий для

- Ранее сохранённые фото не удаляются и не обрезаются. С заполненным лимитом
  нельзя добавить новые; старые записи и R2 не изменены.
- Локальный тест проверяет семь реальных JPEG, запись/чтение local R2,
  фикстурные метаданные, отказ восьмого, владельца и cleanup частичного сбоя.
- Генератор больших тестовых JPEG теперь потоковый, без необязательной
  оптимизации Huffman, и запускается отдельно для каждого размера. Это устраняет
  расход памяти генератора 100 Мп на данном 4-ГБ компьютере; размеры и проверки
  реального декодирования не уменьшены. Настройки JPEG в приложении не менялись.

## Подготовленный полный путь и его границы

Выбор до 7 фото → последовательная серверная нормализация → маленькое превью
640 px → последовательный upload → повторная серверная проверка → R2/metadata
→ существующая защищённая выдача. Оригинал не декодируется в браузерный canvas.
EXIF/GPS/APP/COM удаляются; ориентации EXIF 1–8 проверены реальными пикселями
локального кодека. Один плохой снимок не уничтожает удачные выбранные.

Реальный локальный кодек проверяет JPEG/PNG/WebP, JPEG >12 МиБ, 12/24/48/50/100
Мп, пропорции и отсутствие обрезки. Это **не сертификация Cloudflare/iPhone**.
Настоящее HEIC/HEIF-декодирование провайдером ещё не проверено — согласование
контейнера и MIME не считается такой проверкой.

Выбранный Cloudflare Images binding ограничен 20 000 000 байт, 100 000 000
пикселей и стороной 12 000 px. **108/200 Мп и произвольный размер не поддержаны
этим путём.** Снять проверки недостаточно: нужен другой проверенный серверный
декодер/сервис. Поэтому обещание «абсолютно любой файл проходит» не дано.
[Ограничения Cloudflare](https://developers.cloudflare.com/images/get-started/limits/).

## Конкретный блокер выпуска

Read-only Worker settings вернули 200: binding Images отсутствует. Images stats
и subscription API вернули 403/10000: текущий план не удалось подтвердить.
`marketo-staging` — **живой jevu.kz**, а не отдельный тестовый сайт.

Попытка запустить отдельный `wrangler dev --remote` с тестовыми изображениями
заблокирована системой разрешений ДО запуска: операция в аккаунте Cloudflare
требует отдельного согласия. Обход не предпринимался. Никакой платный план,
Worker, binding, БД, RLS, миграция, аккаунт пользователя или объект R2 не менялся.

Следующее необходимое разрешение: временная удалённая проверка Cloudflare Images
без изменения действующего JEVU. Подключение сервиса на live-сайте — отдельный
шаг после проверки возможностей и допустимой стоимости. По документации Free
включает 5000 уникальных преобразований в месяц без автоматического списания за
превышение; квота при этом может остановить новые преобразования. Подготовленный
путь выполняет две обработки, это не 5000 загруженных фотографий.
[Тарифы Cloudflare](https://developers.cloudflare.com/images/pricing/).
