# Вывод PWA из эксплуатации — 27 сентября 2026

Исходный код: `stage3-staging`, `e5a7757`. Исходная production-версия
`23537814-f8d0-419f-b8ac-df37097aad20` получала 100% трафика.
Снимки конфигурации, замеры и браузерные профили сохранены локально в
gitignored `artifacts/pwa-removal/`. Секретов в документации и коммите нет.

## Удаление и переход

Удалены установка/обновление PWA, регистрация SW, Web App Manifest, standalone
метаданные, offline shell и маршрут, два maskable PNG, их генерация, install UI/CSS
и переводы. PWA-пакетов/Workbox/Serwist/Web Push в зависимостях не было:
`package.json` и lockfile не требуют изменения. Обычные логотипы, favicon,
bookmark-иконка, SEO, viewport и внутренние Vite/RSC manifests сохранены.

Фактическая регистрация Chrome и история опубликованного кода подтвердили
`/sw.js` со scope `/`. Других опубликованных адресов не обнаружено. Для проверки
сохранены настоящий старый профиль Chrome и точная копия SW в
`tests/pwa/legacy-sw.js` (только тест, не public artifact).

Единственные переходные исключения:

- `public/sw.js`: install/skipWaiting → activate/claim → удаление известных
  PWA-кэшей → unregister. Нет fetch/push/sync, offline fallback или новых подписок.
- `public/_headers`: только `/sw.js`, JavaScript без редиректа, no-store/no-cache
  для браузера и CDN, root scope.
- `lib/browser/retire-pwa.ts` и `components/legacy-pwa-cleanup.tsx`: после рендера
  обновляют только существующую старую регистрацию, ограничивают ожидание,
  unregister и повторяют безопасную очистку при восстановлении сети.

Точные исторические кэши: `marketo-shell-v2`, `marketo-static-v3`…`v10`,
`jevu-static-v1`. Проверены история файла и фактический CacheStorage.
Другие имена, регистрации с другим script/scope, cookies, localStorage,
sessionStorage и IndexedDB не очищаются. Reload/Clear-Site-Data отсутствуют.
Открытые формы не перезагружаются; после следующего обычного открытия controller
должен быть null. В offline невозможно получить замену SW; unregister и повторное
онлайн-открытие завершают переход.

Не удалять эти исключения в этом релизе. Удаление допустимо отдельным релизом
после принятого владельцем срока поддержки возвращающихся установок и проверки
достаточного периода обращений к старому endpoint. Для долго отсутствующих
устройств endpoint разумно сохранять: очистку отключённого устройства и удаление
значка из ОС этот механизм не обещает.

## Подтверждённые задержки

1. Витрина скрывала весь первый кадр, пока не декодированы **все** его фото.
   Теперь данные/геометрия открывают карточки и текст, а каждая фотография имеет
   свой placeholder/decode/error. Подготовка текущей/соседней страницы, сохранение
   предыдущего декодированного кадра при ротации и абсолютные часы не изменены.
2. Запрос витрины после смены города мог навсегда занять single-flight promise.
   Теперь общий deadline 10 секунд действует на заголовки **и тело**; ошибка
   открывает явную повторную попытку, не превращается в демо/пустой успех.
3. Home запускал чтение категорий после showcase RPC. Независимое чтение теперь
   запускается параллельно. Fixture trace: до категории начинались после окончания
   showcase; после все четыре запроса стартовали в пределах 0,2 мс друг от друга.
   Число запросов не увеличилось. SSR-снимок витрины и правила демо сохранены.

### Разделение эффектов

Три сохранённые production-сборки: исходная, только удаление PWA, итоговая.
Chromium/Mac, 1440×1000 DPR1, guest, loopback и одинаковые синтетические данные,
без CPU/network throttling. 3 повтора. Cold — новый профиль браузера;
warm — повтор того же URL в том же профиле. Серверный кэш не сбрасывался между
повторами. Значения — медиана/диапазон времени появления DOM полезного содержимого,
не универсальная пользовательская статистика, не INP. Статика локально без gzip.

| Сценарий, мс | До | Только без PWA | Итог |
|---|---:|---:|---:|
| Главная cold | 44 (38–112) | 45 (39–111) | 43 (43–54) |
| Главная warm | 37 (36–38) | 28 (27–31) | 24 (19–29) |
| Каталог cold / warm | 42 / 33 | 40 / 28 | 40 / 27 |
| Объявление cold / warm | 39 / 33 | 41 / 25 | 41 / 26 |
| Гостевой профиль cold / warm | 59 / 34 | 61 / 33 | 50 / 21 |
| Гостевой чат cold / warm | 56 / 46 | 60 / 28 | 48 / 29 |

Удаление PWA убрало 3 запроса на каждом из пяти маршрутов; главная cold:
54 → 51 запрос, 801 → 775 KiB. Само по себе это **не доказало большого ускорения**.
Полные диапазоны, TTFB, LCP, long tasks, запросы и объём — в `lab-*-browser.json`.
В этих коротких локальных выборках long tasks >50 мс не зарегистрированы.

Отдельный воспроизводимый тест настоящего production React/CSS витрины:
первое фото 80 мс, соседнее 4000 мс; 3 холодных повтора.
Видимое первое фото: **4060 (4038–4062) → 109 (108–139) мс**;
готовый текст: **4060 → 42 (39–74) мс**. Геометрия карточек сохранена.
Это устранение ожидания, а не ускорение сети/декодера.

## Публикация и сохранённые контракты

Production build использует gitignored `.env.production.local`; никакие
fixture Supabase values не используются в публикуемом артефакте.
Deployment: обычный `wrangler deploy` с generated config, после commit/push
в `stage3-staging`. `keep_vars`, Images, R2, cron и серверный Worker сохраняются.
Флаги automatic moderation/approval/rejection/external AI остаются **ON**,
shadow остаётся **OFF**, как на фактическом baseline этой задачи.
Миграций, изменений Auth/RLS/правил/ролей/published_at/expires_at/VIP/X2/bump нет.

После deploy проверить 100% traffic version, совпадение client asset с локальной
сборкой, settings/bindings, `/sw.js` JavaScript/no-store, 404 manifest/offline,
новый браузер и сохранённый старый profile (без ручной предварительной очистки).
Повторить read-only production navigation/performance smoke. При критической
регрессии доступен штатный Wrangler rollback к сохранённой исходной версии;
удалённые PWA-кэши не восстанавливаются rollback, auth/drafts не затронуты.
