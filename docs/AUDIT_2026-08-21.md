# Marketo v1.0 — итоговый аудит PWA, каталога и Cloudflare

Дата проверки: 21 августа 2026 года.

## Что было исправлено

- Единое дерево каталога вынесено в `lib/catalog-config.ts`: 14 основных разделов, 228 узлов, до трёх уровней вложенности, RU/KK-названия, `parentId`, порядок, активность, подсказки поиска и атрибуты.
- `CategoryPicker` на мобильном рендерит только текущий уровень. Пустой поиск больше не создаёт в DOM всё дерево; глобальный поиск ограничен 40 совпадениями и возвращает полный путь.
- `CategoryCascade` использует то же дерево в каталоге. После выбора родителя показывается только следующий уровень.
- Каталог синхронизирует с URL запрос, категорию, город, сортировку, цену и `f_*`-атрибуты; фильтры реально влияют на результат и счётчик.
- Формы публикации используют тот же `CategoryPicker`, общий справочник географии и унаследованные настройки категории. Проверен путь `Транспорт → Легковые автомобили → Кроссоверы и внедорожники` и выбор Петропавловска.
- Динамические характеристики проверены для транспорта, смартфонов, недвижимости, работы и услуг. В работе нет автомобильных фильтров и подсказок.
- Исправлены слои, safe-area, прокрутка и блокировка фоновой страницы для mobile category/location/filter/PWA-панелей.
- Исправлены реальные действия главной: CTA ведут на `/publish` и `/search`, поиск отправляет `q` по кнопке и Enter.
- Убраны пустые интерактивные элементы: действия карточки объявления, composer чата и решение модерации теперь имеют обработчики и честные состояния, не изображающие сохранение в ещё не подключённую Supabase.

## Android/iPhone PWA

- Manifest: стабильный `id`, `start_url` внутри `scope`, `display: standalone`, `display_override`, `prefer_related_applications: false`.
- Подготовлены фирменные PNG `any` и `maskable` 192×192 и 512×512.
- Старый служебный favicon заменён фирменным и вынесен в версионированный `marketo-favicon-v2.svg`.
- Apple touch icon 180×180 и `appleWebApp.capable` сохранены.
- Service worker использует cache version `marketo-static-v5`, network-first для навигации, не precache-ит HTML/manifest/favicon, очищает старые cache version.
- Механизм обновления: waiting worker → `SKIP_WAITING` → `controllerchange` → reload; предусмотрен тайм-аут и touch-friendly кнопка.
- Android-инструкция различает установку приложения и обычный ярлык. После выкладки старый ярлык/приложение с буквой W необходимо удалить один раз и установить Marketo заново, поскольку launcher Android кеширует identity/icon уже установленного приложения.

## География

- Единый typed dataset `lib/geography.ts` содержит Казахстан, 17 областей, 3 города республиканского значения и 90 городов.
- Один и тот же `LocationPicker` используется в каталоге и публикации; поиск Петропавловска проверен в production preview.

## Cloudflare и Linux permissions

- `wrangler.jsonc`: Worker `marketo-kz`, main `dist/server/index.js`, assets `dist/client`, compatibility date `2026-05-22`.
- `nodejs_compat` задан один раз в `wrangler.jsonc`; в `vite.config.ts` отсутствуют и `nodejs_compat`, и `compatibility_flags`.
- Сгенерированный `dist/server/wrangler.json` содержит ровно `['nodejs_compat']`, main `index.js`, assets `../client`.
- Все `.sh`: `build-verified.sh`, `install-ci.sh`, `sites-env.sh`, `validate-artifact.sh`.
- `sites-env.sh` подключается через `source`, когда его exports должны остаться в текущем shell; самостоятельная проверка запускается через `bash`.
- Все npm-команды вызывают `.sh` через `bash`.
- Полный `npm test` был выполнен после `chmod 0644` всех четырёх shell-файлов и завершился успешно. Ручной `chmod +x` для GitHub → Cloudflare не требуется.
- Cloudflare Workers Builds использует Node.js 22 по умолчанию; проект фиксирует совместимость `>=22.13.0` в `package.json` и lockfile.

## Что нельзя честно подтвердить автоматически

- Реальную установку, launcher icon, standalone window и системную клавиатуру следует финально проверить на физическом Android и iPhone после новой Cloudflare-публикации.
- Полноценные Auth, реальные объявления, сообщения, избранное и решения модерации зависят от будущих Supabase adapters/credentials. Текущий UI показывает честные empty/required-account состояния и не создаёт фиктивные данные.
- Внешний `wrangler deploy` не выполнялся: это изменило бы опубликованный Worker и требует Cloudflare credentials/явной авторизации. Production artifact и итоговая конфигурация Wrangler проверены локально; ранее подтверждённая GitHub → Cloudflare конфигурация не изменена.
